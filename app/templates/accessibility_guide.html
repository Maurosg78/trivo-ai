Guía de Accesibilidad de TRIVO-AI

Esta guía explica los estándares de accesibilidad implementados en TRIVO-AI y proporciona buenas prácticas para mantener y mejorar la accesibilidad del sitio.

Nota: La accesibilidad es un proceso continuo. Esta guía se actualiza regularmente para asegurar que nuestra aplicación cumple con los estándares actuales.

Introducción a WCAG 2.1

Las Pautas de Accesibilidad para el Contenido Web (WCAG) 2.1 establecen cómo hacer el contenido web más accesible para personas con discapacidades. En TRIVO-AI, nos esforzamos por cumplir con el nivel AA de WCAG 2.1.

Perceptible

La información y los componentes de la interfaz deben ser presentables a los usuarios de manera que puedan percibirlos.

Operable

Los componentes de la interfaz y la navegación deben ser operables para todos los usuarios.

Comprensible

La información y el funcionamiento de la interfaz deben ser comprensibles.

Robusto

El contenido debe ser lo suficientemente robusto para que pueda ser interpretado por una amplia variedad de agentes de usuario.

Características de Accesibilidad Implementadas

Navegación y Estructura

  • Enlaces de omisión (skip links) para saltar al contenido principal Nivel A
  • Estructura de encabezados semántica y jerárquica Nivel A
  • Texto alternativo para todas las imágenes Nivel A
  • Navegación coherente en todas las páginas Nivel AA
  • Indicadores visibles de foco para la navegación por teclado Nivel AA

Ejemplo de skip link:

<a href="#main-content" class="skip-link">Saltar al contenido principal</a>

<main id="main-content" tabindex="-1">
    <!-- Contenido principal -->
</main>

Formularios

  • Etiquetas (labels) asociadas a todos los campos de formulario Nivel A
  • Mensajes de error accesibles y descriptivos Nivel A
  • Agrupación lógica de elementos relacionados con fieldset y legend Nivel AA
  • Autocompletado para campos comunes Nivel AA
  • Indicación clara de campos obligatorios Nivel AA

Ejemplo de campo de formulario accesible:

<div class="form-group">
    <label for="email" class="form-label required-field">Correo Electrónico</label>
    <input type="email" class="form-control" id="email" name="email" 
           required aria-required="true" autocomplete="email">
    <div class="form-text" id="emailHelp">Nunca compartiremos tu correo.</div>
</div>

Colores y Contraste

  • Relación de contraste de al menos 4.5:1 para texto normal Nivel AA
  • Relación de contraste de al menos 3:1 para texto grande Nivel AA
  • No se usa el color como única forma de transmitir información Nivel A
  • Modo oscuro para reducir la fatiga visual Nivel AAA
  • Soporte para preferencias de contraste alto Nivel AAA

Responsive y Dispositivos Táctiles

  • Diseño responsive para todos los tamaños de pantalla Nivel AA
  • Objetivos táctiles con tamaño mínimo de 44x44px Nivel AAA
  • Espaciado adecuado entre elementos interactivos en dispositivos táctiles Nivel AAA

ARIA y Atributos Semánticos

  • Uso de landmark roles (main, nav, header, footer) Nivel A
  • Atributos aria-label para elementos sin texto visible Nivel A
  • Atributos aria-expanded para elementos colapsables Nivel AA
  • Atributos aria-live para actualizaciones dinámicas Nivel AA

Ejemplo de uso de ARIA:

<nav aria-label="Navegación principal">
    <button class="navbar-toggler" type="button" data-bs-toggle="collapse" 
            data-bs-target="#navbarNav" aria-controls="navbarNav" 
            aria-expanded="false" aria-label="Mostrar menú de navegación">
        <span class="navbar-toggler-icon"></span>
    </button>
</nav>

Pruebas de Accesibilidad

TRIVO-AI incluye herramientas para comprobar automáticamente la accesibilidad utilizando axe-core. Para ejecutar una comprobación de accesibilidad en cualquier página:

  1. Busca el botón flotante "Comprobar Accesibilidad" en la esquina inferior derecha.
  2. Haz clic en él para iniciar la evaluación de la página actual.
  3. Revisa el informe generado que muestra problemas encontrados y posibles soluciones.
  4. Puedes descargar el informe para su análisis posterior.
Importante: Las pruebas automáticas pueden detectar aproximadamente el 30% de los problemas de accesibilidad. Complementa siempre con pruebas manuales y pruebas con usuarios reales.

Buenas Prácticas para Desarrolladores

HTML Semántico

  • Usa elementos HTML5 semánticos (main, nav, article, section, etc.)
  • Estructura jerárquica correcta de encabezados (h1-h6)
  • Usa listas (ul, ol) para grupos de elementos relacionados
  • Utiliza tablas solo para datos tabulares, no para layout

Imágenes y Multimedia

  • Proporciona texto alternativo descriptivo para imágenes
  • Usa atributo alt vacío (alt="") para imágenes decorativas
  • Proporciona subtítulos y transcripciones para videos
  • No uses GIFs o animaciones que parpadeen más de 3 veces por segundo

Interactividad y JavaScript

  • Asegura que toda funcionalidad sea accesible por teclado
  • Mantén indicadores visibles de foco al navegar con teclado
  • Usa ARIA para componentes personalizados
  • Prueba con lectores de pantalla (NVDA, VoiceOver, JAWS)

Formularios

  • Asocia siempre elementos label con sus inputs
  • Agrupa campos relacionados con fieldset y legend
  • Proporciona mensajes de error descriptivos y accesibles
  • Añade atributos autocomplete adecuados a los campos
